## Overview

The Interaction Check endpoint identifies known drug-drug interactions using approved interaction data sources. It returns severity levels, summaries, and recommended actions. Medications that cannot be normalized are returned in the `unknowns` list.

## Endpoint

`POST /v1/ai/interactions/check`

## Authentication

All requests require authentication via an internal API key. See the [Authentication](/docs/guides/authentication) guide.

For common request fields like `caller`, `actor_context`, `authorization_context`, and `locale`, see the [Common Request Structure](/docs/guides/common-request-structure) guide.

## When to Use

Use this endpoint when you need to check for interactions between two or more medications. It is suitable for pharmacy dispensing systems, prescription validation, and clinical decision support workflows.

### Request Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `input.medications` | object[] | Yes | At least 2 medications to check |
| `input.medications[].name` | string | Yes | Medication name |
| `input.medications[].dose` | string | No | Optional dose information |
| `input.patient_context` | object | No | Patient context for personalized assessment |

## Example Request

```bash
curl -X POST http://localhost:8000/v1/ai/interactions/check \
  -H "Content-Type: application/json" \
  -H "X-Zam-AI-Key: <your-api-key>" \
  -d '{
    "actor_context": {
      "actor_type": "patient",
      "actor_id": "user-101",
      "role": "patient"

      ],
      "patient_context": {
        "age": 68
      }
    }
```

### Response Fields

| Field | Type | Description |
|-------|------|-------------|

## Example Response

**(See the full JSON response above.)** The response lists detected interactions with severity, a human-readable summary, recommended action, source citations, and confidence scores.

## Error Responses

| Code | Description |
|------|-------------|
| `200` | Interaction check completed |
| `400` | Validation error (fewer than 2 medications) |
| `401` | Missing or invalid API key |
| `422` | Invalid request body |
| `500` | Internal service error |

## Notes

<Note>
  The endpoint uses deterministic interaction data where available and never invents
  interaction severity. Medications that cannot be normalized are returned in
  `unknowns` rather than silently excluded.
</Note>

<Warning>
  Missing patient context is reported but does not block the check. However,
  results may be less precise without complete patient information.
</Warning>
