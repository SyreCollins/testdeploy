## Overview

Triggers automated evaluation runs for testing and regression detection. Used to validate prompt changes, model updates, and retrieval improvements against known test datasets.

## Authentication

Requires a valid admin-level internal API key via the `X-Zam-AI-Key` header. See the [Authentication](/docs/guides/authentication) guide for key types and usage.

---

## Run Evaluation

`POST /v1/admin/evaluations/run`

### When to Use

Run evaluations after making changes to prompts, models, or retrieval pipelines to detect regressions and validate improvements against known datasets.

### Request Body

```json
{
  "dataset_id": "medical_qa_core_v1",
  "prompt_version": "medical_qa:v1",
  "model_config": "default",
  "run_type": "regression"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `dataset_id` | string | Yes | Identifier for the evaluation dataset |
| `prompt_version` | string | Yes | Prompt version to evaluate |
| `model_config` | string | No | Model configuration to use (default: `"default"`) |
| `run_type` | string | No | Type of run (`"regression"`, `"benchmark"`, or `"exploratory"`) |

### Example Request

```bash
curl -X POST http://localhost:8000/v1/admin/evaluations/run \
  -H "Content-Type: application/json" \
  -H "X-Zam-AI-Key: <admin-api-key>" \
  -d '{
    "dataset_id": "medical_qa_core_v1",
    "prompt_version": "medical_qa:v1",
    "model_config": "default",
    "run_type": "regression"
  }'
```

### Response

`200 OK`

```json
{
  "request_id": "7d9827b8-9f42-4f4f-8e4a-3c4b4fd973a1",
  "status": "success",
  "workflow": "evaluation",
  "result": {
    "run_id": "eval_run_001",
    "dataset_id": "medical_qa_core_v1",
    "status": "queued",
    "created_at": "2026-07-17T10:30:00Z"
  },
  "audit": {
    "trace_id": "ai-trace-909",
    "prompt_version": "evaluation:v1",
    "model_provider": "provider-name",
    "model_version": "model-version"
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `result.run_id` | string | Evaluation run identifier |
| `result.dataset_id` | string | Dataset being evaluated |
| `result.status` | string | `"queued"`, `"running"`, `"completed"`, or `"failed"` |
| `result.created_at` | datetime | Run creation timestamp |

---

## Error Responses

| Code | Description |
|------|-------------|
| `200` | Evaluation run created |
| `400` | Validation error |
| `401` | Missing or invalid API key |
| `422` | Invalid request body |
| `500` | Internal service error |

<Tip>
  Use `regression` runs for CI/CD pipelines to catch regressions before deploying prompt
  or model changes to production. Use `benchmark` for comparing model versions.
</Tip>

<Note>
  Evaluation runs are asynchronous. The initial response returns `"status": "queued"`.
  Check run results through the evaluations results endpoint (coming soon).
</Note>

## More Examples

### JavaScript (fetch)

```javascript
const response = await fetch('http://localhost:8000/v1/admin/evaluations/run', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-Zam-AI-Key': '<admin-api-key>'
  },
  body: JSON.stringify({
    dataset_id: 'medical_qa_core_v1',
    prompt_version: 'medical_qa:v1',
    model_config: 'default',
    run_type: 'regression'
  })
});

const data = await response.json();
console.log(data);
```

### Python (requests)

```python
import requests

response = requests.post(
    "http://localhost:8000/v1/admin/evaluations/run",
    headers={
        "Content-Type": "application/json",
        "X-Zam-AI-Key": "<admin-api-key>"
    },
    json={
        "dataset_id": "medical_qa_core_v1",
        "prompt_version": "medical_qa:v1",
        "model_config": "default",
        "run_type": "regression"
    }
)

print(response.json())
```
