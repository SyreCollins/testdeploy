## Overview

Returns the current health status of the Zam AI service. Used by load balancers, orchestrators, and monitoring systems to verify the service process is alive and responding.

## Endpoint

```
GET /v1/health
```

## Authentication

See the [Authentication](/docs/guides/authentication) guide.

## When to Use

Call this endpoint to confirm the service process is running. No authentication is required — it is designed for load balancers and monitoring infrastructure.

## Request

No request body. No query parameters.

## Example Request

### cURL

```bash
curl http://localhost:8000/v1/health
```

### JavaScript (fetch)

```javascript
fetch('http://localhost:8000/v1/health')
  .then(res => res.json())
  .then(data => console.log(data));
```

### Python (requests)

```python
import requests

response = requests.get("http://localhost:8000/v1/health")
print(response.json())
```

## Response

```json
{
  "status": "ok",
  "service": "zam-ai",
  "version": "0.1.0",
  "environment": "production"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | Always `"ok"` if the process is running |
| `service` | string | Service name identifier |
| `version` | string | Current deployed version |
| `environment` | string | Deployment environment (`production`, `staging`, `development`) |

## Error Responses

| Code | Description |
|------|-------------|
| `200` | Service is healthy |
| `500` | Service process is unhealthy |

## Notes

<Note>
  This endpoint performs a lightweight process check only. For dependency-level
  health, use the [Readiness Check](/docs/endpoints/02_ready) endpoint.
</Note>
